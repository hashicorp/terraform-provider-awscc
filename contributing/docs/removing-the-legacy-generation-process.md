# Removing the legacy generation process

A checklist for punchlist item D ("Adopt — phase 2: delete the redundant legacy
machinery"), including the folded-in design items 13 (checkout-file retirement)
and 15 (delete legacy generators/directives/`make` targets). Follow this once
bigdiffer has been the weekly driver for several clean release cycles and nobody
has needed the
[legacy fallback](generating-the-provider-with-bigdiffer.md#fallback-the-legacy-process).

This is a **transient tracking doc**, like `generation-punchlist.md` — delete it
once the checklist below is done.

## Before you start

Confirm both of these, in order. Stop and do not proceed if either fails.

1. **Several real weekly cycles have run on bigdiffer with no fallback to the
   legacy process.** "Several" is a judgment call, not a fixed number — the
   point is confidence, not a calendar date. If anyone reached for
   `generating-the-provider.md` in that window, the fallback is still needed;
   wait longer.
2. `go test ./internal/tools/bigdiffer/... -run TestFullCorpusParity` passes
   (0 drift against the full corpus). This is the **last** time this test proves
   bigdiffer's owned engine is byte-identical to the legacy one: step 1 converts
   it to a committed-file comparison because the legacy engine it compares
   against is about to be deleted. Do not remove the legacy engine while this
   test — in its current bigdiffer-vs-legacy form — would have caught a real
   divergence.

## What is being deleted

The legacy machinery is self-contained and nothing bigdiffer ships depends on
it — `TestNoLegacyGeneratorImports` enforces that `internal/tools/bigdiffer/**`
imports neither `internal/provider/generators/**` nor `internal/naming`. That
boundary is what makes the deletions below safe. In scope:

- `internal/provider/generators/` — **all** of it (`allschemas`, `common`,
  `import-examples`, `plural-data-source`, `resource`, `schema`, `shared`,
  `singular-data-source`), including the dated `available_schemas.*.hcl`
  snapshots under `allschemas/` that fed `make biglister` / `make bigdiffer`.
- `internal/provider/{resources,singular_data_sources,plural_data_sources}.go`
  and `internal/provider/schemas.go` — the four legacy `//go:generate` +
  blank-import directive files. `internal/provider/registrations_gen.go` is
  bigdiffer's replacement and already carries every registration.
- `internal/update/` — the legacy updater (`makes.go`, `changelog.go`,
  `hcl_parser.go`, `github.go`, `main.go`), superseded by `bigdiffer -update`.
  It imports the legacy generators and `internal/naming`; nothing else imports
  it.
- `internal/naming/` — the legacy naming/pluralization package. Once the two
  consumers above are gone it is dead; `internal/tools/bigdiffer/naming` is
  bigdiffer's owned copy and the only one still used.

**Keep:** everything under `internal/tools/bigdiffer/**` (including
`internal/tools/bigdiffer/codegen` and `internal/tools/bigdiffer/naming`), and
the aggregates bigdiffer emits (`registrations_gen.go`,
`import_examples_gen.json`).

> [!NOTE]
> The `internal/tools/bigdiffer/codegen/*.tmpl` templates emit a
> `// Code generated by generators/…/main.go` provenance header into the
> generated files. That string is intentional and byte-parity-critical — leave
> it exactly as is. Editing it to say "bigdiffer" would rewrite every generated
> file. It is a literal in the output, not a live reference, so the step-1 grep
> below will not (and should not) match it.

## The checklist

Do these in order. Each step leaves the tree buildable and the suite green —
build and test after every step, not just at the end. If a deletion leaves a
dangling reference, stop and re-scope; do not comment the reference out and move
on.

1. **Decouple the parity test from the legacy engine.** `TestFullCorpusParity`
   and its helper `runLegacyArtifact` (`internal/tools/bigdiffer/parity_test.go`)
   currently `go run generators/{resource,singular-data-source,plural-data-source}/main.go`
   to distinguish real drift from a merely-stale committed file. That comparison
   only made sense while the legacy engine existed to disagree with. Rewrite the
   test to compare bigdiffer's output against the **committed** `*_gen.go`
   (a mismatch is now a straight failure), and delete `runLegacyArtifact`. This
   is a runtime `go run`, not a compile-time import, so `go build`, `go vet`, and
   `TestNoLegacyGeneratorImports` will **not** flag it — you must do this by
   inspection, before step 2. Verify the rewritten test still passes with the
   legacy engine present (it just no longer calls it).

2. **Retire the suppressions checkout file (design item 13).** bigdiffer still
   reads `internal/update/suppressions_checkout.txt` via `parseCheckout`
   (`main.go`, `update.go`) to explain retained-but-pinned rows; that file is
   about to be deleted with `internal/update/` (step 4). Fold it into
   `frozen_since` per `bigdiffer-design.md` §5:
   - For every type pinned in `suppressions_checkout.txt`, ensure it carries a
     `frozen_since` (and reason) in `all_schemas.hcl`.
   - Delete `parseCheckout`, the `-checkout` flag, the `defaultCheckout`
     constant, and the `checkout` parameter threaded through `normalize` /
     `runCheck` / `runUpdate`.
   - `go run ./internal/tools/bigdiffer -check` must still pass with no
     retained-row anomalies.

3. **Delete the legacy generator engine and directive files.**
   - `rm -rf internal/provider/generators`.
   - Delete `internal/provider/resources.go`,
     `internal/provider/singular_data_sources.go`,
     `internal/provider/plural_data_sources.go`, and
     `internal/provider/schemas.go`.
   - Grep for any surviving directive sites with
     `grep -rn 'go:generate.*generators/'` — expect none.
   - `make build` and run the full test suite. Nothing should reference the
     deleted packages.

4. **Delete `internal/update/`** (`rm -rf internal/update`) — the legacy
   updater, now unreferenced (step 1 removed the parity test's use of the
   generators; step 2 removed bigdiffer's read of its checkout file). Build and
   test.

5. **Delete `internal/naming/`** (`rm -rf internal/naming`). With the generators
   and `internal/update` gone it has no remaining importers. Build and test.
   Optionally simplify `TestNoLegacyGeneratorImports` — its
   `terraform-provider-awscc/internal/naming` entry is now guarding against a
   package that no longer exists (harmless, but stale).

6. **Delete the legacy `make` targets.** Remove: `cleanschemas`, `suppressions`,
   `schemas`, `resources`, `singular-data-sources`, `plural-data-sources`,
   `biglister`, `bigdiffer` (the legacy dated-snapshot-diff target — **not**
   `internal/tools/bigdiffer`), `update` (the legacy updater target),
   `docs-import`, `docs-fmt`, `docs`, `docs-all` (the legacy docs flow, replaced
   by `bigdiffer -docs`), and the staged-commit helpers `commitrefresh`,
   `commitschemas`, `commitresources`, `commitdatas`, `commitdocs`.
   - Update the `all:` target (it lists `schemas resources
     singular-data-sources plural-data-sources … docs-all`, all being removed) —
     redefine it in terms of `bigdiffer-generate` + `build`, or delete it.
   - Grep the `GNUmakefile` for any deleted target used as a dependency of one
     you're keeping, and fix those chains.
   - **Keep:** `build`, `test`, `testacc`, `lint`/`golangci-lint`/`importlint`,
     `modern`/`modern-check`, `tools`, `smoke`, `newbranch`, and the
     `bigdiffer-*` shortcuts — the bigdiffer weekly workflow uses `newbranch`
     and `smoke`.

7. **Delete `generating-the-provider.md`** (the legacy runbook), then sweep for
   dangling links: `grep -rl 'generating-the-provider.md' .` currently matches
   `contributing/CONTRIBUTING.md`, `contributing/docs/resource-behavior.md`,
   `contributing/docs/suppressed-and-frozen.md`,
   `contributing/docs/generation-punchlist.md`, and
   `internal/tools/bigdiffer/README.md` (plus
   `generating-the-provider-with-bigdiffer.md`, handled in step 8, and this doc,
   deleted in step 12). Fix or remove every referrer.

8. **Update `generating-the-provider-with-bigdiffer.md`:**
   - Delete the entire "Fallback: the legacy process" section — there is no
     fallback anymore.
   - Delete the "What bigdiffer replaces" table's framing as a *replacement*
     (there is nothing left to compare against); fold anything still useful into
     plain prose, or delete the section outright.
   - Remove the `> [!NOTE]` callout about `registrations_gen.go` superseding the
     three legacy directive files — they are gone, so "supersedes" and "during
     the transition both may be present" are no longer true. Replace with a
     one-line statement that `registrations_gen.go` is the sole registration
     mechanism, kept honest by `bigdiffer -check`.
   - Rename the doc (drop "with bigdiffer" — there is no other way to generate
     the provider anymore) if that reads better standalone; not required, use
     judgment.

9. **Tighten `internal/tools/bigdiffer/main.go`'s `checkRegistrationUpToDate`.**
   This is the one **behavior change**, not just a deletion — easy to forget
   since nothing will fail loudly if you skip it.
   - Today the `errors.Is(err, os.ErrNotExist)` branch returns `""` (absence
     allowed) because the legacy directive files still registered every type.
     That condition is now false.
   - Change that branch to return a problem string, so `-check` fails if
     `registrations_gen.go` is missing or deleted by hand once it is the *only*
     registration mechanism.
   - Update the function's doc comment (drop the "Absence is not a failure"
     paragraph) and flip the `TestCheckRegistrationUpToDate` "absent" sub-test
     (`run_generate_test.go`) so absence now asserts a problem; rename its
     "allowed during the transition" comment.

10. **Full verification pass**, same rigor as any other change to this package:
    `gofmt`, `go vet`, `go build ./...`, the full `bigdiffer` suite fresh
    (`go clean -testcache` first, including the rewritten `TestFullCorpusParity`
    and `TestCheckRegistrationUpToDate`), `-race -short`, `impi` with CI's actual
    flags (`impi --local . --scheme stdThirdPartyLocal --ignore-generated=true
    ./...`), and offline `go run ./internal/tools/bigdiffer -generate` +
    `-check`. A live `-update` run is optional here — it hits AWS (~13-minute
    crawl, needs credentials) and adds nothing the offline checks do not cover
    for a deletion-only change.

11. **Update `generation-punchlist.md`:** mark item D (and the folded-in items
    13/15) done, then delete the punchlist entirely per its own stated lifecycle
    once nothing else is outstanding.

12. **Delete this doc.**
